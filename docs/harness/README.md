# 可复用的 Harness 执行规范

Harness 应当用明确的能力、受控的执行环境和可追溯证据完成当前请求，并在交付完成后结束。这里将 ocean-intelligent-detection 最近的更新抽象为八项可迁移模式，供知识库、数据分析和其他工具型智能体使用。

本项目已落地项目级 Skill 发现与加载、显式文件沙箱策略、简洁回复规则，以及幂等运行配置生成。其余模式按业务需要接入；水声算法、物理参数和特定文件格式保留在原项目 Skill 中。

## 更新概览

| 通用更新 | 解决的问题 | harness-wiki 的应用 |
| --- | --- | --- |
| 按需加载 Skill | 仅凭名称猜接口，重复扫描仓库，加载无关手册 | 使用 SDK 目录和 `skill` 工具，新增知识检索 Skill |
| 显式执行边界 | 将提示词约束当作文件权限，继承环境改变默认边界 | 固定 `workspace-write` 与 `ask`，配置 Shell 超时 |
| 事实与处理选择分开 | 伪造事实，或为每个可逆参数反复追问 | 检索默认模式直接使用，真实歧义一次汇总 |
| 减少重复执行 | 工具已经返回摘要，仍重复读取、计算和核验 | 证据足够即回答；仅补查具体缺口 |
| 简洁且完整的交付 | 重复任务、过程旁白、路径清单淹没结论 | 结论在前，必要依据和引用在后 |
| 控制范围与结论强度 | 自动追加分析，把描述性结果说成通过验收 | 普通问答不追加体检；无证据部分单独限制 |
| 按输入与产物路由能力 | 相邻 Skill 冒充缺失能力，上下游产物混用 | 当前知识 Skill 只检索，治理交给业务工具 |
| 管理运行配置与任务生命周期 | 重写配置触发监听器，任务已失败仍等待完成 | 配置内容不变就不重写；异步生命周期另按宿主接入 |

## Skill 发现与执行

Skill 是按任务加载的操作契约。它说明触发范围、输入、执行方法、输出和证据边界；执行可以使用业务工具，也可以使用受控脚本，不能把读取 `SKILL.md` 当作已经完成操作。

目录由 SDK 解析，保持“名称和描述 → 正文 → 必要参考”的渐进加载。讨论某个 Skill 的具体输入、参数或产物时，也应加载正文；问候和普通概念解释直接回答。脚本与参考文件相对于工具返回的 Skill 基目录解析，避免猜测所在路径。

本项目统一使用以下顺序，并关闭默认的个人目录：

```text
skills/
.agents/skills/
.dsh/skills/
```

同名 Skill 按上述自定义根顺序选择。目录隔离控制能力来源，不等于校验了每个 Skill 的内容。部署镜像包含项目 `skills/`，本地两个隐藏目录中的扩展需由部署者显式复制或挂载。

[skills.mjs](../../backend/harness/skills.mjs) 通过真实 `SkillRegistry` 读取目录，`GET /api/skills` 只返回名称和描述，不启动模型。聊天端通过相同的 `HARNESS_SKILL_DIRS` 使用 SDK 的目录监听和加载工具。当前默认定位为网优，[wireless-echo-mem](../../skills/wireless-echo-mem/SKILL.md) 使用原理来源工具，必要的网优资料补查复用 `lightrag_query_data`，无需另写 HTTP 客户端。

需要脚本的 Skill 可采用下面的执行形状，具体步骤由其契约决定：

```text
加载 Skill → 取得输入事实 → 必要的 review/preflight → 执行 → 使用结果摘要 → 交付并结束
```

预检用于身份、参数、范围和资源的一致性检查。原请求已经授权执行且预检通过时，可以继续；预检本身不授予额外权限。涉及变更审批的业务仍必须通过业务工具的审批流程。

## 文件沙箱与业务审批

文件边界必须由实际执行器落实。共享策略、受控 Shell 和文件工具应指向同一工作区；部署不能仅在 persona 中写“只操作工作区”。

本项目在 [rag-kb profile](../../backend/dsh/home/profiles/rag-kb/cordis.patch.yml) 显式设置：

```yaml
- id: sandbox-policy
  config:
    mode: workspace-write
    workspaceRoot: !!js process.cwd()

- id: approval
  config:
    policy: ask

- id: bash-sandbox
  config:
    cwd: !!js process.cwd()
    timeoutMs: 60000
    maxTimeoutMs: 300000
```

SDK base 已提供沙箱执行器，这次迁移固定项目默认策略。上述配置覆盖部署默认值；SDK 的会话策略和获得批准的单次提权仍由其权限服务处理。不能把文件 `workspace-write` 表述成远程 API、网络、密钥或全部进程行为的完整隔离。

本地可写和远程业务写入是两个边界。知识库文档替换、退役和图谱修改继续使用原工具的人工审批；入库和失败重试保持现有免审批契约，各写入口仍记录审计。Skill 加载、参数预检和工作区写权限均不替代受控操作的审批。不得借 Shell 或直接 HTTP 绕过业务变更入口。

沙箱验证必须包含实际允许写入和拒绝越界写入，并检查执行器返回的 `sandbox.mode` 与 `sandbox.enforcement`。本次本地集成验证使用 macOS Seatbelt；Docker/Linux 部署需独立验证对应后端，容器存在或配置写了沙箱名称都不能代替执行证据。沙箱不可用时保留失败，不自动回退到无限制执行。

## 事实与自主处理选择

对未知项先分类，避免“禁止猜测”演变成凡事都问用户。

| 类别 | 处理原则 | 例子 |
| --- | --- | --- |
| 来源事实 | 从输入元数据、用户说明或有效产物取得，不伪造 | 文档版本、数据采样率、用户选择的输入 |
| 确定性推导 | 依据事实计算，记录必要依据 | 样本数和采样率推导时长 |
| 可逆处理设置 | 保持用户选择，其余按任务或契约默认处理 | 检索模式、绘图格式、输出新目录 |
| 影响核心交付的歧义 | 先做独立部分，再一次汇总缺口 | 两份制度冲突，用户要求裁决有效版本 |
| 受控变更 | 按业务审批与实际权限执行 | 修改知识库、覆盖既有结果、外部发送 |

自主选择不能记录为“用户逐项确认”。需要确认时说明阻断事实、可选方案和影响，不把默认参数、格式选择或可计算的描述指标逐项推回用户。

缺少某种证据，通常只限制依赖该证据的结论。没有真值不报准确率，没有基线不报改善量，没有验收阈值不做工程通过判定；仍可交付有依据的描述统计。在知识库场景中，未检索到资料应说“当前检索暂无依据”，不能推断制度不存在。

原项目探索性波束分析中的名义声速、同步假设和未标定状态依赖具体任务授权，不能推广为任意领域都可以自行补齐事实。

## 用工具结果减少重复执行

工具的成功输出应提供回答所需的摘要、关键数值、覆盖范围和必要产物位置。入口可以集中处理可访问性、参数有效性和输出防覆盖，从而减少模型在入口前后重复执行相同检查。

- 摘要足够就直接交付；缺某个必要值时，一次读取对应字段。
- 复用仍有效的结果。输入、范围、参数或版本变化时，只重做受影响步骤。
- 生成报告使用已有结果，不因用户要求导出而重新运行算法。
- 独立读取可以合并；有依赖的调用保持先后关系。
- 保留退出码与完整摘要，不接 `head`、`tail` 或成功 `echo` 掩盖失败。

这些规则减少重复工作，不禁止必要核验。有实际冲突、用户明确要求独立复核或证据已过期时，应执行与问题相称的检查；不能用工具次数少替代正确性。

知识问答追问优先复用当前会话证据。有具体缺口才聚焦补查，无新信息时不重复同一查询。用户明确要求最新版本时重新检索，不能把旧证据直接称作最新。

## 回复简洁且保持证据完整

简洁来自交付结构和停止规则，而不是删掉必要依据或把模型输出上限压得很低。通用 persona 可使用 [提示词模板](prompt-template.md)，业务规则放在自己的 Skill 与工具契约中。

| 请求 | 默认交付 |
| --- | --- |
| 问候 | 一两句话，不加载 Skill、不调用工具 |
| 普通术语 | 每项一句定义、一句用途，按需展开 |
| 常规知识问答 | 一至三段，约150至300字，保留必要引用 |
| 对比或诊断 | 结论、必要对比证据和影响，篇幅随复杂度增加 |
| 已有结果追问 | 直接回答相关结论，只补缺失事实 |
| 保存或导出 | 正式产物链接和一句内容说明 |

上述字数是知识库助手的表达目标，不是强制截断。多条制度、复杂证据或用户要求详细解释时应展开；原项目数值分析默认300至600字也不应机械照搬。

正常回复省略重复任务、工具能力清单、内部编号、调试过程和产物目录。内部细节只有影响结论或用户明确询问时才展开。知识库来源文件与支撑结论的限制必须保留；与回答直接相关的原文图片使用工具返回的 Markdown 和原始 URL。

典型表达：

> 报销须在审批后提交，材料包括发票和费用明细。现有检索未找到跨月期限规定，暂无法判断是否逾期。来源：《差旅报销管理办法》。

这是交付结构示例，不代表本知识库已存在该制度或检索结果。

## 任务范围与能力路由

按用户本轮要交付的内容及输入类型选能力。生成结果、评价已有结果、关联下游产物分别属于不同任务，不能因为名称相近就互相替代。

有多个候选输入且选择会改变结论时，先列清候选并请求选择。上游产物是否可供下游使用，应由 Schema、身份和摘要校验决定；不能从图片、零散表格或评价包拼出不存在的执行输入。

目录缺少请求的能力时，先明确能力缺口及影响，不加载相邻 Skill 来反复证明它们也不能执行。目录只能说明 Skill 是否安装；模型工具、插件、服务和输入契约是否可用，还应由对应运行时判断。原项目的专用路由插件是一个按能力实现的例子，不应把水声关键词正则直接复制到知识库。

任务达到当前交付条件就结束。只检查数据不自动追加频谱分析，只问制度不自动追加知识库体检，只解释方案不自动写草稿文件。用户进一步请求扩展时，再执行相应工作。

## 运行配置与生命周期

[prepareHarnessHome](../../backend/integrations.js) 从 profile manifest 的 `link:` 依赖连接本地插件，避免另外维护插件名称表。生成的配置只包含凭据环境变量名，内容不变时不重写文件，减少监听器受到无效更新的影响。

脚本运行时需要固定解释器和依赖。原项目通过项目 `.venv` 覆盖 `PATH`，清除外部 `PYTHONHOME`、`PYTHONPATH`，将绘图与缓存写入工作区；缺环境时失败，不默默使用系统 Python。当前知识 Skill 调用原生检索工具，不需要引入 Python 环境。

长任务优先使用宿主提供的前台超时或后台 jobs，以及可等待的结果接口，不用 `sleep`、列目录或反复读取产物轮询。调用方应处理完成、失败、取消和超时，并保证资源最终释放。

原项目 `runHarnessTask` 在根任务失败或超时后关闭其持有的 Harness，防止终态后继续等待 idle。迁移到共享知识库子进程时，要保留其他会话的运行；取消单轮任务不能直接关闭全局 Harness。浏览器停止显示也不能等同于后台执行已取消。

本次已迁移配置幂等化；共享进程的完整取消、超时与作业管理需按知识库宿主生命周期另行实现，不能声称已经具备原项目独立任务入口的全部行为。

## 验证方式

```bash
node --test backend/dev/contract-harness.mjs
node backend/dsh/dsh-knowledge/dev/run-tests.mjs
```

新增契约测试使用实际 SDK，验证项目 Skill 优先级、个人目录隔离、知识 Skill 正文与基目录、manifest 插件连接、配置不重复写入、真实 Seatbelt 写入边界，以及生产 rag-kb profile 的启动和关闭。生产 profile 测试使用本地知识服务替身与模型请求哨兵，不调用真实模型或远程知识库。

2026年10月8日本地验证：新增5项 Harness 契约检查全部通过，现有13组知识库测试全部通过，知识检索 Skill 元数据校验通过。文件沙箱测试实际运行且无跳过；验证范围为本机 macOS，尚未验证 Linux 容器后端及真实模型的回复行为。

提示词需要另用真实对话验证：问候不触发工具、知识问答先检索、已有证据追问不重复检索、无命中不编造制度、治理操作等待业务审批。应同时检查答案正确性、工具次数和篇幅。确定性配置测试不能证明模型每轮都会遵守表达目标。
