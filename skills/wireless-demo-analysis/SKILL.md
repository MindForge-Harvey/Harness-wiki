使用实际工具读取场景与历史、计算指标和编译经验，不编写预设答案。场景可按完整业务标题或稳定 ID 读取，无需用户提供特殊前缀。原理和经验编译来自固定 ECHO-Mem 源实现，指标统计是本项目的数据适配层。

用户提供真实数据集工单或 ICOS run_id 时，先使用该工单的输入和已有结果，按 wireless-workorder-orchestrator 的 ICOS 路径处理；没有场景库条目时保留真实记录，不切换为同名合成场景。场景库专属的 reveal_feedback/learn 只用于其自身数据，真实反馈与经验使用原工单账本和历史编译工具。

面向用户使用场景、工单、方案、执行反馈、效果评价、经验更新等业务称呼，直接解释发现与建议。参数优先使用 `parameter_label`，历史来源优先使用 `source_records.label`；正文不展示内部工具名、文件路径和 demo-/SIM-/synthetic- 编号。普通业务回答不使用“演示”“模拟”等用途标签，不以“合成场景”“虚拟参数”等措辞重新添加用途前缀。来源性质由界面的“数据说明”入口与元信息提供，普通回答不附加“数据说明”尾注、用途声明或能力清单。用户询问来源、真实性或当前能力时如实说明：场景库为合成样本，参数与范围未经过厂家认证，未连接现场设备；读取反馈记录不等于操作了网管。

业务分析不需要开发或修复程序，也不必为每个阶段维护 todo。领域工具报错时仅在明确知道输入错误并能修正时重试一次；相同错误不循环重试，不通过 shell、脚本直接 import 服务或预读内部文件绕过领域工具及反馈时序。完成可用的独立分析后报告受阻阶段。系统修复由单独的开发任务处理。

按用户目标自由组合能力，不强制完整闭环。普通分析只完成决策前阶段；只有用户明确要求完整处理、反馈评价、学习或经验更新，才读取反馈并学习。

1. `wireless_demo catalog` 读取可用数据和场景。已知完整业务标题或场景 ID 时直接 `read_case`；标题必须逐字保留“ · ”后的条件后缀，不能将“园区晚高峰接入失败 · 缺少当前参数”替换成“园区晚高峰接入失败”。不确定时先 `catalog` 确认对应条目，再 `read_case`，获取决策前观测、快照、评价判据与时序文件。不要通过文件工具预读 `feedback.private.json`，必须保留先决策后读取结果的顺序。
2. `wireless_data_analyze` 直接使用返回的 `analysis_arguments`，它限定当前小区与 PEER；不要无筛选地分析整份十二场景文件。按 48 个基线窗口与之后的窗口比较，展示 peer_comparisons，说明异常时段、变化幅度与同窗口同步关系；`evidence_check` 中隔离的数据不得参与本单判断。相关性和历史根因标签不能证明本单原因。
3. `wireless_demo compare_candidates` 实际编译或复用初始经验，并运行 ECHO 源排序和值适配。比较候选的样本、历史效果、评分、反证和当前约束；不要预设首项一定适用。候选不足、厂家不匹配、缺当前值时交付缺口，不创造目标值。
4. 解释当前数据怎样支持或反对根因假设，再比较有依据的方案。可用两张短表呈现当前发现、对照、判断影响，以及候选、历史支持、反证、目标值。给出验证项、保护指标和回退条件，不能声称已下发或已通过校准 gate。
5. 反馈与经验更新：从实际返回的候选 ID 中选择，调用 `select_candidate` 冻结依据版本、方案与目标值；用返回的 `decision_id` 调 `reveal_feedback`。该操作读取所选方案对应的反馈记录、保存账本并实际评估前后效果。将结果表述为“反馈记录显示”，不声称自己完成现场下发。报告实际工具状态，数据不足不包装成成功。
6. 调 `learn` 从上述账本导出有来源的 Trace，工具按评价可见时间和七天成熟边界编译新版本。再调 `compare_candidates` 或 `memory` 读取当前版本，比较新增来源、样本、状态与评分；一次新反馈未改变排序时如实说明，不宣称越学越准。

`knowledge_cutoff` 表示经验版本的数据截止时间，内部 `simulated_clock` 是兼容字段。工具可将数据截止推进到反馈可见且满足成熟边界之后，不表示现实中等待了多天或自动采集新观测；日期按北京时间解释并保留时区。新一轮处理可复用相同输入快照，反馈窗口随数据时间平移。旧包保留，重复学习同一 decision 不重复计数。合成样本空间不进入普通 `wireless_history_search` 的生产候选池，不可改成 historical 绕过来源隔离。

用户提供的现场数据可用 `wireless_data_analyze`；实际工单走原工单工具保存和评价。`wireless_workorder export_trace` 可导出已记录的执行事实，长期 Pass/Fail 需明确来源与评价可见时间，描述性改善不自动生成长期评价。后续 `wireless_compile_history` 按来源使用 historical 或 demo 模式。

数据说明与使用问法见 `docs/wireless-network-optimization/demo-guide.md`。
