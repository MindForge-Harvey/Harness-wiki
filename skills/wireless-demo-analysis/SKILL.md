此 Skill 使用可运行工具演示，不直接编写预设答案。数据是完全合成的；问题类型、参数取值、KPI 和反馈均不代表现网事实。`Demo.*` 参数使用演示范围，不援引为厂家配置。原理和经验编译来自固定 ECHO-Mem 源实现，指标统计是本项目新增的数据适配层。

演示任务不需要开发或修复程序，也不必为每个阶段维护 todo。领域工具报错时仅在明确知道输入错误并能修正时重试一次；相同错误不循环重试，不通过 shell、脚本直接 import 服务或预读内部文件绕过领域工具及反馈时序。完成可用的独立分析后报告受阻阶段。需要修复系统应由单独的开发任务处理。

按用户目标自由组合能力，不强制完整闭环。普通分析只完成下面前半部分；只有用户明确要求模拟反馈、学习或完整记忆闭环，才揭示反馈和学习。

1. `wireless_demo catalog` 读取可用数据和场景。已知场景 ID 时 `read_case`，获取决策前观测、快照、评价判据、时序文件。不要通过文件工具预读 `feedback.private.json`；这会破坏本次先决策后揭示的演示。
2. `wireless_data_analyze` 直接使用返回的 `analysis_arguments`，它限定当前小区与 PEER；不要无筛选地对整份十二场景文件输出混杂的分析。按 48 个基线窗口与之后的窗口比较，展示 peer_comparisons，说明异常时段、变化幅度与同窗口同步关系；`evidence_check` 中被隔离的当前数据不得参与本单判断。相关性和历史根因标签不能证明本单原因。
3. `wireless_demo compare_candidates` 实际编译/复用初始经验，并运行 ECHO 源排序和值适配。比较候选的样本、历史效果、评分、反证和当前约束；不要预设首项一定适用。候选不足、厂家不匹配、缺当前值时直接交付缺口，不创造目标值。
4. 对用户解释数据怎样支持或反对根因假设，再比较有依据的方案。常规交付可用两张短表：当前发现/对照/判断影响，以及候选/历史支持/反证/目标值。保留简短案例或记忆 ID，少写内部字段。给出验证项、保护指标及回退条件，不能声称已下发或已通过校准 gate。
5. 完整闭环演示：从实际返回的候选 ID 中选择，调用 `select_candidate` 冻结依据版本、方案与目标值；用返回的 `decision_id` 调 `reveal_feedback`。该操作保存预置模拟执行反馈并实际调用前后效果评估。报告真实工具状态，数据不足不包装成成功。
6. 调 `learn` 从上述账本导出有来源的合成 Trace，等待模拟评价可见与七天成熟边界后实际编译新版本。再调 `compare_candidates` 或 `memory` 读取新版本，比较新增来源、样本/状态/评分变化；一次新反馈未改变排序时如实说明，不宣称越学越准。

演示时钟可推进到未来模拟日期，必须说明是模拟时间，日期按北京时间解释并保留时区。反馈窗口随新一轮演示平移，不能说系统在现实中等待了多天或自动采集了新观测。旧包保留，重复学习同一 decision 不重复计数。演示空间不进入普通 `wireless_history_search` 的生产候选池；不要把演示数据改成 historical 规避这个边界。

任意真实数据可用 `wireless_data_analyze`；实际工单走原工单工具保存和评价。`wireless_workorder export_trace` 可导出已记录的执行事实，长期 Pass/Fail 需明确来源与评价可见时间；描述性改善不自动生成长期评价。后续 `wireless_compile_history` 仍按真实/演示模式分别调用。

数据说明与丰富演示问法见 `docs/wireless-network-optimization/demo-guide.md`。
