# ECHO-Mem 历史驱动分析契约

用于工单分析、指标解释、根因判断、参数应用、方案比较与评价。这里只消费历史与当前输入；需要保存工单、实际反馈、评价或编译时由 `wireless-memory-engineering` 编排。问候和纯 ECHO-Mem 机制解释按各自入口回答。

根因、方案和评估的具体判断方法见 [历史决策方法](echo-decision-workflow.md)，按本轮阶段读取。该方法给出 ECHO-Mem 源实现对应关系、如何迁移历史经验以及每阶段应交付的判断；源码核对按需进行，不替代历史检索。

## 必经动作：实际检索历史

先提取问题/参数、已知厂家与制式，再调用 `wireless_history_search`。缺厂家、当前值或 KPI 仍须检索，不把补数作为查历史的前提。已有同问题、同筛选、同版本的检索结果可复用；新增观测改变根因方向时聚焦补查。参数语义、历史应用和研究经验已在结果中时直接复用。

工具自动查询固定案例快照、参数语义和研究结论，并发现本地冻结包中的六类记忆。用户指定 `package_ids` 则固定这些版本；as_of 默认本次查询时间，用户提供带时区决策截止时按该时间排除更晚的包/快照。固定案例摘要缺逐条结果可见时间，不能充作严格时序回放依据。

分别解释结果：

- `history_match`：说明命中的案例/记忆及与当前条件的异同。命中不代表可直接复用。
- `no_history_match`：说明实际检索范围与未命中；保留查到的参数机制、研究经验和条件性假设，标明缺对应历史工单支持。当前未命中不能推成知识全局不存在、任何厂家均无此参数，不能凭命名风格判定虚构。
- `search_incomplete`：说明具体来源未读取成功，使用其他有效材料；不能把读取失败说成没有案例。
- `production_workorder_connector.status=not_connected`：说明完整真实生产工单库尚未接入。本地真实归档包与匿名实际案例摘要仍可使用，保留其范围。

参数语义、研究经验、演示与真实工单属于不同证据。空案例结果不能通过假设例子补成实测历史；已有经验也不能因缺完整生产库而被丢弃。

参数语义或方案名称只提示机制和潜在处理方向，没有执行记录时不能称历史上处理过或常用；语义条目数量不能推成原因概率、统计支持或方案优先级。当前指标缺对象、窗口或定义时先限制可比性，不能借历史词典补出当前事实。

未命中是有效的检索产物，说明范围和缺口后交付，不换同义词反复查同一个已完整返回的固定目录。只有用户明确指定网优文档时按需补查原文；不能因未命中调用 kb_diagnosis_submit、反馈或图谱修改工具，普通分析也不保存假工单。

## 将源实验步骤用于当前分析

固定来源提交：`e734ac032a7dc671878d05cd40d2b31b68d156fc`。能力的源 Skill 与研究消费者分别见 [ECHO 能力目录](echo-capabilities.md)。下列研究路径相对 `echo-mem-reproducibility/`，原文可通过 `wireless_echo_query(view="implementation", source_path=...)` 按需核对。它用于核对方法，不能替代历史检索。

| 源步骤与实现 | Harness 中的执行方式 | 必须交付的判断 |
| --- | --- | --- |
| 决策输入隔离：`pipeline/shadow/context.py` | 将当前决策时已知现象、观测、参数与事后执行/评价分开；按用户指定截止读取历史包 | 当前判断用了哪些已知事实；事后结果留到评价 |
| 案例与六类记忆召回：`pipeline/shadow/retrieve.py` | `wireless_history_search` 返回案例、根因、策略、组合、风险与反证；保留参数身份与场景差异 | 为什么可比、哪里不匹配、哪些经验能迁移 |
| 正向/复核/反证分池：同上 | 工具将 validated/reusable 策略与组合放正向池，restricted 放复核池，反证类型/状态放反证池；其余保留为背景 | 候选支持、需复核项与限制依据；未验证经验不升级 |
| 当前证据组织：历史标签与画像契约 | 使用当前真实 KPI/MR/KQI/告警/参数；有工单 ID 时通过 `build_evidence` 对齐对象、窗口和口径 | 历史根因提示与当前支持/反对证据的对应关系 |
| 候选比较：`pipeline/selection/plan_ranker.py` | 按需用 wireless_echo_decision(rank_candidates) 实际执行源四项排序；select_candidate 按源 Shadow 约束选择表内 ID | 推荐与备选的理由；源包评分、本轮排序分与字段命中数分别说明 |
| 目标值适配：`pipeline/selection/action_value_selector.py` | 有策略与真实快照时 adapt_value 实际执行源值选择器；已知候选用 wireless_parameter_check 检查；缺值交付方向和待补条件 | 历史前后值、当前值、候选值、约束和回退参考分别说明，不推定现值 |
| 反证复核：`pipeline/selection/failcohort_veto_gate.py` | 核对历史失败是否匹配同参数、方向和边界，说明复核/限制条件 | 风险来自什么、什么条件下停止或回退；校准 gate 尚未接入 |

当前可执行检索、源状态分池、源 ranker、源值选择器、受限候选物化、证据核对与声明约束检查。完整结构导航、校准 gate 与端到端研究回放仍未接入。模型执行源 Skills 的证据解释与定性比较；没有调用消费者时不能说运行过其算法，也不生成自动放行证书。Harness 按依赖和用户目标组合能力，不强制固定阶段顺序。

## 分析产物

按任务深度交付历史检索结果、当前与历史比较、支持/反对依据、结论或候选方案以及关键缺口。保留简短案例/工单标识；引用记忆时保留包版本、memory_id 和源 Trace。解释材料后再按需给来源链接，不要求用户自行读源码获得答案。

多动作整单结果保持组合作用域，推荐与实际执行分开；未知厂家/制式/单位不视为兼容。源评分按其有效样本与画像解释，不当作当前成功概率，不跨包重复累加工单支持。缺 KPI 前后值只说明已记录整体评价，不给改善幅度。

评价候选时比较历史支持、反证和当前适用差异；评价执行后效果时核对实际反馈、可比前后观测与业务判据。两者共用可用历史，不把预期建议当作实测结果；简单完整数据的差值计算无需额外检索，涉及历史效果、适用性或经验更新时实际查历史。
